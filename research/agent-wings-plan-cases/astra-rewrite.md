# Agent Wings 基础设施规划与仓库边界

## 1. 当前阶段与本轮边界

本计划是直播展示平台、sandboxing、Wings Ray 三个独立项目的协调入口：确定职责、开工依赖和阶段出口，不代替各仓实现规划或赛事规则。当前阶段仍是仓库初始化、参考实现调研和首版规划，不是服务上线或隔离验收。

**状态口径：** 下文的仓库基线、托管状态和历史运行情况均按已提供文档记载。本次只修订文档，没有重新核验 Git、远端、宿主或服务。绝对路径和网址用于项目定位；未提供的源码、原始证据及外部页面保持未核查，不把资料记载当成本次实测。

已确定的方向：

- OBS Studio 负责推流；首条候选路线为专用 Web 展示页加 OBS Browser Source。
- sandboxing 参考 kappa-box 的 Windows 实现，但须使用本项目资源独立验证；参考切片不构成正式准入依据。
- Wings Ray 基于 New API 建立公开 fork，具体定制等待需求单。它对应赛事资料中的 HFUT Router；下文 Router 指该模型接入服务。
- 赛事既定的 Pi 0.87.1 改造起点、首轮统一改进包和多目标评分不在本轮改动。

本次不执行安装依赖或 OBS/WSL/Docker、创建发行版或虚拟机、修改网络/防火墙/代理、配置密钥、启动服务、付费模型测试及运行验收。既有托管和推送授权不扩展为上述操作的授权。

## 3. 执行链路与权威来源

```text
可信评测 runner / 评分器（实现及部署归属待明确）
  ├─ 使用 sandbox 生命周期与文件通道 → 隔离环境中的参赛 Agent
  │                                      └─ 受限推理权限 → Wings Ray → 指定模型
  ├─ 收集实际产物、运行/费用记录 → 硬性检查、模型裁判与人工复核
  └─ 发送可公开事实 → 展示平台可信接入层 → OBS 展示页 → OBS Studio → 直播服务
```

| 事实或操作 | 权威归属 | 不能替代它的东西 |
| --- | --- | --- |
| 实例生命周期、资源与网络边界 | sandbox runtime 和真实探针 | 页面状态、配置项、API 接受参数或容器产品名。 |
| 模型请求与结算记录 | Router/上游记录及可信对账 | Agent 自报 token、前端估算或参赛者可修改的客户端标签。 |
| rollout 身份、输入版本、起止与样本归属 | 可信 runner 的正式记录 | OBS 时间轴、浏览器计时或导播手工选择。 |
| 正式结果与综合成绩 | 评分器及复核流程 | 暂定分、一次成功、演示回放或 Agent 自述。 |
| 直播内容与焦点选择 | 展示平台/导播 | 修改实际任务、预算、评分或重跑任务的权限。 |

runner/评分器的实现、部署与维护归属仍是待决项。真实联调前须明确其责任主体、运行位置、生命周期控制和正式记录保存方式，不能默认塞入 sandbox、Router 或展示页。本规划不新建第四个仓库，也不以三个仓库已建立代替这项决定。

### 5.2 本项目必须建立的边界

- 改进包、extensions、Skills、依赖脚本、产物及生成代码均按不可信内容处理。安装和构建也应在隔离构建区完成，不在直播宿主或含管理凭据的环境中裸跑队伍脚本。
- 保护其他队伍、隐藏评测数据与评分器、宿主私人文件、局域网服务，以及 Router、平台和 OBS 管理面。可信管理员与 hypervisor 属于信任根，不宣称抵抗已控制宿主的攻击者。
- 普通任务的外网访问按赛事和题目规则允许；禁网任务仍保留受控 Router 数据面。非授权的模型服务、管理接口、其他队伍及内网/metadata 路径须强制拒绝，并以实际探针验证；能推理或使用同机 localhost 都不是隔离证明。
- 只接受预注册环境和策略，不接受任意宿主挂载、特权容器或引擎 socket。长期上游密钥留在可信侧，运行侧仅持有可撤销、用途受限的推理权限。
- 在目标比赛主机重验文件、网络、资源、凭据、会话、产物快照及故障回收；覆盖实际资源压力、越界路径/链接、持续写入、断连、超时和子进程残留。配置存在或命令返回成功均不能代替这些探针。
- 不复用 kappa-box 的实例、发行版、端口、网关、密钥或缓存所有权。复用代码前另查许可、依赖和维护成本。

首条真实切片覆盖准备、创建、运行目标任务、产物收集、终止和删除；它只证明链路跑通。对抗探针及独立审阅另行构成准入证据。候选不能兑现边界时，停止该候选并保留失败原因，不自动降级为裸进程执行。完整矩阵以 [sandbox 首版规划](../../../agentwings-sandbox/docs/PLAN.md)为入口。

## 6. Wings Ray：需求驱动的准备边界

据 [fork 规划](../../../wings-ray/WINGS_RAY_PLAN.md)，完整克隆、本地开发基线与公开 fork 已建立；没有安装依赖、启动服务、执行上游 Docker Compose、连接数据库或配置渠道密钥。公开代码不等于服务上线，当前基点也不等于正式部署版本。

需求单到达后，逐项形成“需求、边界、优先级、实现方式、验收路径”的差异表，再决定改动范围：

1. **上游配置即可满足：** 用真实行为验证，不以管理 UI 中存在选项判定通过。
2. **需要接口适配：** 先明确调用、权限和计量语义，优先保持小而可维护的差异。
3. **必须改代码：** 明确行为差异、失败测试、兼容范围、迁移与回滚后实施。

赛事集成至少要回答：Pi 0.87.1 与指定模型的实际协议是什么；工具调用、流式响应和所需多模态字段能否按原语义传递；赛事身份如何限制到指定模型、关联子代理请求并撤销权限；断流、取消、重试、并发和延迟结算如何对账。协议能调用、费用能核验和任务产物正确是不同的验收结论，不能相互替代。

上游密钥、渠道控制与 Router 管理权限不交给参赛进程或 OBS 页面。向 runner/评分器提供可信计量，向平台提供经授权的脱敏信息，不能把原始敏感日志或管理 API 当作展示接口。赛事的指定模型和成本归属要求是集成约束，不扩大为 Router 所有用户的产品限制；账号、支付、校园认证或多租户等未确认需求不在本轮预设。

Fork 维护仍须遵守：

- 保留 New API 完整历史；`upstream` 用于读取和同步，不向上游 push 或提 PR。同步前检查本地改动，记录引入的 SHA，不在 dirty 工作树上覆盖更新。
- 公开发布前检查所有待推送提交，而非只看最终文件；不得包含凭据、私有评测材料或运行数据。
- 保留上游 AGPLv3、LICENSE、NOTICE、第三方许可、作者归属和原项目可见链接要求；对外提供修改后的网络服务前，核对对应版本并落实源码提供与发布义务。许可要求来自 fork 规划，原始条款正文未在本次复核。
- 正式部署 pin 到明确版本/commit 与构建产物 digest，不随 `latest` 漂移。平台和 sandbox 的许可证不在此代选；代码复用或分发关系改变时再核对相关义务。

需求单到达前停留在 R0，不开展定制开发或部署；主机、数据库、备份、HTTPS、域名、网络路径和容量也不能由上游部署示例默认决定。

## 7. OBS 展示平台：先证实一条真实展示链路

推荐专用只读 Web 展示页，由 OBS Browser Source 加载；后台导播控制与公开画面分离。OBS 负责合成、编码、录制和推流，不另建 RTMP 服务。首版不承担报名、社交、弹幕、视频分发服务器或新的评分引擎。

路线按展示所需的证据推进：

1. 取得一次真实 Pi 0.87.1 任务的事件与产物样本，核对实际源接口和可公开字段。优先读取结构化事实，不从 TUI 屏幕文本推断任务完成。
2. 实现一队、一题的状态、脱敏摘要和产物入口。开发时可使用回放，但必须醒目标识，不能称作 live 验收。
3. 用一次真实 rollout 打通 OBS 本地录制，保留录像与源事件对照，检查字体、缩放、裁切、长文本及费用/时间显示。
4. 再增加并列画面、评分板和异常恢复；在授权的测试直播间验证推流，并取得实际接收端画面及链路指标。

数据在进入浏览器前，由可信接入层完成身份校验、白名单、脱敏和发布控制。原始工具返回不无差别上屏，密钥模式过滤只作补充；不要求公开不可取得的模型内部思维。终端文本、Markdown、文件名和超链接按不可信输入处理；转义控制序列与 HTML，禁止任意脚本执行或自动打开链接。

OBS 不加载队伍提供的任意 URL，不共享后台登录态或管理凭据。网页、文档和图片产物经受控收集及独立预览/渲染边界后展示。OBS 场景、浏览器参数、日志与导出材料也须检查，推流密钥不得进仓库。

展示必须保留状态差异：

- 排队、运行、结束、失败和数据中断分别显示；缺数据、未结算不显示为零，并标明最后更新时间。
- 并列画面不把不同题或不同 rollout 阶段伪装成实时同条件对比；评分板标明样本数、评分版本和暂定/最终状态。
- 重复、乱序、缺段、重放和结算修订不能造成重复累计。页面刷新时间不替代源端时间。
- 刷新页面、断开 OBS、切换或紧急遮挡画面只影响展示，不重启任务、不修改运行状态、不删除原始证据。

视频、音频、直播服务、延迟、拓扑和技术栈仍待第 4 节输入决定。材料记录的阶段尚无可运行 UI、本地录像或推流验收结果；这些不能从本节的路线描述中推定为已完成。

## 8. 跨仓接口：先走通语义，再冻结形状

真实样本和 Router 需求单明确前，不冻结 API 路径、JSON schema 或共享 SDK。先用一条真实 rollout 明确以下交接，再把观察到的语义固化为接口与失败测试。

| 环节 | 必须保留的语义与证据 |
| --- | --- |
| 准备与绑定 | 可信侧关联队伍、题目、rollout、冻结改进包、输入/环境版本、实例与模型请求；不靠参赛者可修改的标签或请求头证明归属。每次独立 rollout 从约定基线恢复，缓存策略按任务公示执行，不跨任务、跨队或跨 rollout 继承答案和运行改进。 |
| 正式运行 | runner 记录任务正式交付时点。主 Agent、子代理、工具内模型调用、自动重试和并行候选都归入同次运行；包内自动适配可以存在，但不得变成队伍在首轮正式任务间人工换包或在评测期间更新远程方案的通道。 |
| 结束与收集 | 区分正常结束、失败、超时、取消及控制故障。墙钟从任务正式交付起计，至最终产物提交且相关执行结束为止；报错或超时未产生最终产物时计至终止。产物采集须区分 live copy 与稳定快照，确保封存内容与评分器读取内容一致，终止能收敛相关子进程。 |
| 结算与评分 | 运行结束不等于费用已最终结算。Router/上游记录经可信对账后归属样本；并行时间不简单相加，费用须累计。不可核验费用不默认零；Agent 自身的报错、超时、错误答案和无效产物保留在完整计分样本中，不因表现差而剔除。主办方环境或模型服务故障是否作废补跑，依技术团队认定和公示规则处理，并保留原记录。 |
| 发布与恢复 | 原始证据、可公开事件、暂定/最终分数分别保存与授权。重复、乱序、断线恢复和历史重放不能触发重复计费、重复计分或新运行；隐藏评测数据、凭据和私人内容不流入直播。 |

展示端断线不得影响正式运行；可信执行控制端断线时，谁继续持有任务、谁按何种超时规则终止、恢复后如何对账，仍须在 runner 方案中明确并验证，不能由页面状态决定。

sandbox 对 Router 的访问仅限受限推理数据面；Router、平台与 OBS 的管理面必须与参赛运行网络分离。上述关联与状态语义由真实记录证明，不能以“有统一 ID”或“接口调用成功”代替权限、计量和生命周期验证。
