# Agent Wings 基础设施规划与仓库边界

## 1. 本轮范围与依据

为 Agent Wings 建立三个独立项目：直播展示平台、sandboxing、Wings Ray。当前阶段仍是仓库初始化、参考实现调研和首版规划，不是服务上线或隔离验收。本计划明确三个项目的职责、下一步输入、联调顺序及正式准入所需的证据，不替代赛事规则或各仓库的实现规划。

已确定：OBS Studio 负责推流；sandboxing 参考 kappa-box 的 Windows 实现但必须独立验证；Wings Ray 基于 New API 建立公开 fork，具体定制等待需求单。赛事既定的 Pi 0.87.1、首轮统一改进包和质量、平均成本、平均时间的多目标评分不在本轮改动。

本轮不执行安装 OBS/WSL/Docker、创建发行版或虚拟机、修改网络/防火墙/代理、配置密钥、启动服务、付费模型测试或运行验收。后续环境变更、真实调用和推流分别需要对应授权，仓库托管授权不代表这些操作已获授权。

本文依据随附的赛事草案、三个项目的规划和 Windows 调研记录整理。关于仓库初始化、克隆、远端、提交基点和历史运行结果的描述，均是材料记载，不是本次重新检查 Git、访问远端或运行探针所得。`D:/Projects/...` 为原项目位置描述；未随材料提供的源码、README、Git 元数据、原始证据文件及外部网址保持未核查。

## 3. 分层与权威来源

```text
可信评测 runner / 评分器（实现及部署归属待明确）
  ├─ 使用 sandbox 生命周期与文件通道 → 隔离环境中的参赛 Agent
  │                                      └─ 受限推理权限 → Wings Ray → 指定模型
  ├─ 收集实际产物、运行/费用记录 → 硬性检查、模型裁判与人工复核
  └─ 发送可公开事实 → 展示平台可信接入层 → OBS 展示页 → OBS Studio → 直播服务
```

| 事实或操作 | 权威归属 | 不能替代它的东西 |
| --- | --- | --- |
| 实例生命周期、资源与网络边界 | sandbox runtime 和真实探针 | 页面状态、配置项或容器产品名。 |
| 模型请求与结算记录 | Wings Ray/上游记录及可信对账 | Agent 自报 token、前端估算或参赛者可修改的客户端标签。 |
| rollout 身份、输入版本、起止与样本归属 | 可信 runner 的正式记录 | OBS 时间轴、浏览器计时或导播手工选择。 |
| 正式结果与综合成绩 | 评分器及复核流程 | 暂定分、一次成功、演示回放。 |
| 直播内容与焦点选择 | 展示平台/导播 | 修改实际任务、预算、评分或重跑任务的权限。 |

三个仓库不因此自动包含评测编排与评分实现，也不新建第四个仓库。runner/评分器由哪个项目承载、在哪里运行、由谁管理，仍是待决项，必须在真实联调之前落实。展示页存在、sandbox 能执行命令或 Router 能转发请求，均不能代替这项工作。

参赛改进包、extensions、Skills、安装/构建脚本、依赖、工具返回和运行中生成的代码与产物，均按不可信内容处理。隔离边界保护其他队伍、隐藏评测材料、评分器、平台与 OBS 管理面、Router 管理权限及上游密钥、宿主私人文件和非授权内网服务。可信管理员与 hypervisor 属于信任根，不宣称能够抵抗已控制宿主的攻击者。

### 5.2 候选与最小验证范围

WSL2 + Docker Desktop + OpenShell 是 Linux 工作负载的优先验证候选；独立 Linux 虚拟机保留为对照路线。专用 Windows 虚拟机、Windows Sandbox 或原生 Windows backend 面向明确要求原生 Office/桌面的任务，需单独验证系统版本/许可、无人值守操作、网络与资源约束、重置及产物导出。调研中 OpenShell 原生 Windows MXC 仅为观察项，记载的交互、网络强制和恢复能力不足，选型前需要重新核对，不能沿用旧支持结论。

应用兼容性与隔离强度分别判定。Linux 冒烟不能代替原生 Windows 验证；候选无法兑现边界时停止该候选并记录原因，不自动退回裸进程执行。

| 验证对象 | 真实路径与通过依据 |
| --- | --- |
| 准备与创建 | 在隔离构建区准备真实改进包；只接受预注册环境和策略，不执行未经检查的宿主安装脚本，不接受任意宿主挂载、特权容器或引擎 socket。 |

## 7. 展示平台：真实事件到 OBS 本地录制

推荐专用只读 Web 展示页 + OBS Browser Source，后台导播控制与公开画面分离。OBS 负责布局合成、编码、录制及推流，首版不自建 RTMP 或视频分发服务，也不新增报名、社交、弹幕或评分引擎。该路线仍为候选，现有材料没有可运行 UI、录像或推流验收结果。

先取得一队、一题、一次真实 Pi 0.87.1 rollout 的源事件与产物样本，确认实际接口和可公开字段；再实现单队状态、操作摘要、必要日志和产物入口，进入 OBS 本地录制。并列画面、评分板和授权测试直播间推流随后扩展，不能用开发回放跳过真实联调。

| 展示内容 | 必须保留的区分 |
| --- | --- |
| 队伍、任务与 rollout 状态 | 排队、运行、结束、失败、数据中断分别显示，页面刷新不是运行重新开始。 |
| 单队操作与产物 | 只展示必要的脱敏事实，不要求曝光不可获得的模型内部思维，不把 Agent 自述当成完成证明。 |
| 并列观察 | 标明题目和 rollout 阶段，不伪装成实时同条件对比。 |
| 评分、费用与时间 | 标明样本完成数、评分版本、数据更新时间及暂定/最终；缺数据或待结算不能显示为零。 |
| 回放与接入异常 | 回放醒目标记；断线显示最后更新时间和中断状态，不能把旧数据继续称为 live。 |

可信接入层在服务端执行身份校验、字段白名单、脱敏、聚合与发布控制。原始记录留在可信侧，OBS 展示页不得获得导播凭据、Router 管理 API 或 sandbox 控制接口。密钥模式过滤只能补充白名单，不能代替它。

终端文本、Markdown、文件名、超链接和产物先按不可信输入处理，转义控制序列和 HTML，不执行任意脚本或自动打开链接。网页、文档、图片经受控收集与独立预览/渲染边界，不让 OBS 加载队伍提供的任意 URL，不共享后台登录态。同机 localhost 不是隔离证明；OBS 场景、浏览器参数、日志和导出物也需检查凭据泄露，推流密钥不进入仓库。

接入处理重复、乱序、缺段、断线恢复、历史回放和最终结算修订。刷新、切画面、OBS 断开或展示端重启均不得干扰正式任务；展示端不得自动重启任务，重放也不能重复累计费用、样本或分数。准备独立遮挡/暂停画面，紧急切换只影响直播，不删除证据或改运行状态。

平台阶段按 P0 接口盘点 → P1 展示切片与开发回放测试 → P2 一条真实 rollout 的 OBS 本地录制 → P3 异常与多队 → P4 授权测试直播间推流推进。P2 保留录像与源事件对照，检查字体、缩放、裁切及长文本，并向权威计量核对费用与时间；P4 要有实际接收端画面和链路指标，未配置账号不能声称推流通过。视频规格、音频、直播服务、延迟、部署拓扑和技术栈仍待选择，容量不以估计替代实测。

## 8. 跨仓接口先确定语义

在真实样本和 Router 需求单明确前，不冻结 API 路径、JSON schema 或共享 SDK。先沿一条真实 rollout 确认下列语义，再把可用结论固化到各仓接口：

| 语义 | 需要共同确认的关系 |
| --- | --- |
| 身份与版本 | 队伍、任务、rollout、输入版本、冻结改进包、环境/实例与模型请求由可信侧关联。不同仓库版本独立记录，不能靠参赛者标签或直播焦点证明样本归属。 |
| 执行与样本 | 开始、相关执行全部结束、失败、超时、取消、重试和正式补跑分别记录；单次 rollout 内的并行、重试与候选筛选不是新增的免费样本。 |
| 费用与时间 | 请求消费、运行状态和结算状态分开；迟到记录或结算修订可以对账，重复/乱序事件不重复累计。墙钟时间由可信运行边界产生，不由浏览器或 OBS 决定。 |
| 重置与缓存 | 独立 rollout 从公示基线开始；哪些安装材料、缓存可复用事先明确并各队一致执行，不保留上一次正式运行的答案、会话或生成改进。 |
| 产物与裁判 | 收集和封存的产物与评分器、Judge、人工复核读取的版本一致；硬性检查、模型理由、人工意见及最终成绩均可关联回正式样本。 |
| 授权与公开 | 原始证据、可公开事件和分数分别保存与授权。隐藏材料、凭据及私人内容不流入直播；受限 Router 数据面与 Router/平台/OBS 管理面分离。 |
| 断线与恢复 | 明确谁持有任务、谁有终止权限、如何处理控制端断线或孤儿实例；展示故障不接管生命周期，恢复后对账而不是重新发起任务。 |

计量遵循赛事评分草案：从任务正式交给 Agent 到最终产物提交且相关执行结束计算墙钟时间，包含模型等待、工具、自检与重试；并行分支时间不简单相加，但费用累计。初始化、冷暖启动及缓存是否计入由任务参数表决定，实际读取正式题、分析任务或生成产物不能移出计量区间。

正式统计使用公示次数的完整样本。Agent 自身错误、超时、无效产物的费用、时间和状态保留，不挑选成功运行；经技术团队确认的主办方环境或模型服务故障，依公示规则认定作废/补跑，并保留原始记录。合法额外工具、服务或资源费用按统一口径核验，不把不可核验费用默认记为零，也不允许通过未申报资源转移开销。

这组语义是联调约束，不新增评分公式、权重、rollout 次数、处罚或晋级规则。对外展示的暂定分不能替代全部 rollout、硬性检查与人工复核后的最终成绩；疑点也不能直接作为违规结论。

## 9. 推进顺序与阶段出口

各仓可在输入齐备且已获授权的范围内推进，不因其他仓尚有待定项就停下独立文档工作；但缺少真实来源、环境授权或关键边界证据时，不跨越对应的运行阶段。I0 的仓库建立情况以材料记载为当前基线，不以本次文档核对冒充实际 Git 验收。

| 阶段 | 重点 | 阶段出口与阻断条件 |
| --- | --- | --- |
| I0：规划与分仓 | 三个独立仓库、职责、参考结论、Router 上游基点。 | 实施侧可检查文件、Git、远端和历史边界；有规划不等于有生产能力。runner/评分器待决项明确列出。 |
| I1：输入与选型 | 补齐第 4 节输入，确认任务软件、主机、runner 归属、Router 需求单和直播需求。 | 对下一步所需输入标记已确认/待定，选定可验证候选并获得相应环境变更授权；Router 无需求单不进入定制与部署。 |
| I2：各自纵向切片 | 真实 sandbox 任务、Pi → Router → 指定模型的协议与费用对账、真实事件进入 OBS 本地录制。 | 每仓记录实际路径与版本，证明链路可用；mock/回放仅用于开发测试，不能算真实验收。切片不代表完整隔离或正式成绩可用。 |
| I3：联合与对抗验证 | 跨队隔离、按任务禁网仍可推理、失败/重试/撤销、回收、状态重置、脱敏与展示断连。 | 同一 rollout 的实例、请求、费用、产物、检查与展示证据可关联，异常可解释；任何关键边界未知或失败均不准入正式赛。 |
| I4：演练与发布 | 固定版本与构建产物、容量实测、独立审阅、完整赛事演练及授权推流。 | 登记实际可用的任务/环境范围、回滚方式和故障责任；完整样本与评分可追溯，不能以单次演示代替。 |

各阶段证据记录对应的平台、runner/评分器、Router、sandbox、Pi、OBS 及环境版本，说明使用的输入/改进包、实际路径、观察结果与未覆盖项。原始敏感证据留在授权位置，对外只提供脱敏内容；录像不是唯一运行证据。配置接受、生命周期跑通、协议正确、应用可用、隔离生效、计量完整和推流成功分别判定，不能用一个局部成功覆盖其他未通过项。

关键失败沿实际依赖处理：隔离缺口停止受影响环境的正式资格；计量或身份无法核对时不据此发布最终成绩；展示或 OBS 故障切换中断/遮挡画面，不更改正式执行和原始证据。恢复及版本回滚后，重新验证受影响路径，不能继续引用不再覆盖当前环境的旧证据。显示准确但隔离或计量未通过时，整体联调仍不通过。

## 10. 与赛事规则的关系

| 文档 | 对基础设施的约束 |
| --- | --- |
| [赛事主草案](../releases/1015/Agent_Wings_PLAN_DRAFT.md) | 固定 Pi 0.87.1 起点、指定平台和模型、阶段安排及任务信息边界；准备阶段允许 AIGC，正式运行不得借外部代码生成或其他推理服务绕过指定模型。 |
| [改进包交付说明](../releases/1015/Agent_Wings_DELIVERY_DRAFT.md) | 校对提供完整包、目录外材料、依赖与运行说明，确认环境、版本和文件校验值；首轮一套包跨任务使用，允许包内自动适配，不允许队员在正式任务间人工换包、换配置或注入新提示词。 |

交付材料最晚在校对阶段结束前 36 个小时完整提交，逾期不受理首次提交；不要求队伍提交开发 sessions，不表示技术团队不保留正式运行、计量和产物证据。校对通过只证明部署、运行及合规确认，不代表取得任务分数。正式验证使用确认的起始版本，队伍维护的服务也不能成为包外更新通道；包内逻辑在单次 rollout 中自主生成代码或状态属于运行行为，记录其开销，并在独立 rollout 间按规则重置。

额度注记 (1)：每队或个人约 40 RMB 的专用额度是准备阶段参考测试支持，不是正式评测单题预算、费用上限或评分阈值。禁网任务保留受控的指定 Router 通道；其余任务不另行限制正常网络访问，但仍须遵守指定模型、任务规则及隔离边界。

评分读取真实产物，硬性检查与软性质量分别提供依据；Judge 的模型、版本、rubric 和证据范围在同一任务内一致，产物与工具返回是待评价数据，不能改变裁判指令。正式成绩追溯到冻结版本、全部计分样本、实际产物、检查、模型理由、人工意见及平均成本/时间。任务权重、成本/时间映射、rollout 次数、保障上限、top-k 及异议规则仍由正式公告补齐，本基础设施规划不自行决定。
