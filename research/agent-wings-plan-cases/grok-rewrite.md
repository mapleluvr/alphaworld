# Agent Wings 基础设施规划与仓库边界

## 1. 本轮范围

为 Agent Wings 建立三个独立项目：直播展示平台、sandboxing、Wings Ray。当前阶段是仓库初始化、参考实现调研和首版规划，不是服务上线或隔离验收。

确定项：OBS Studio 负责推流；sandboxing 参考 kappa-box 在 Windows 宿主上的专用 WSL2 / OpenShell / Docker Desktop 路线，但必须在比赛目标主机独立验证，不能把该参考当成已经通过的原生 Windows 隔离；Wings Ray 基于 New API 建立公开 fork，定制需求单后续提供。赛事文本中的 HFUT Router 即 Wings Ray。赛事既定的 Pi 0.87.1、统一改进包和多目标评分不在本轮改动。

不在本轮执行：安装 OBS/WSL/Docker、创建发行版或虚拟机、修改网络/防火墙/代理、配置密钥、启动服务、付费模型测试。后续用户已授权在 `mapleluvr` 下托管和推送仓库：Wings Ray 为 public fork，其余仓库为 private。

本文件汇总三个仓库的首版规划、Windows 调研和 1015 赛事草案，只划定跨仓边界与推进顺序。文中的 commit、证据摘要和“已克隆 / 未启动”等状态，沿用这些材料中的记载及其原有限定。在后续阶段取得对应运行证据之前，这些记载不是对当前比赛主机或 `D:/Projects` 路径的再次测量，也不能代替各阶段出口要求的证据。

下面是草案已经写明、并且会约束后续集成的事项。它们不是本轮要改的评分规则，也还不是已经配置或跑通的系统行为。参数表没有给出的 rollout 次数、权重、分数映射、超时、并发和正式费用上限，继续保持待定，不在本规划中补数值。

- **指定模型。** 正式评测只使用主办方给定平台和指定模型 DeepSeek-V4.1-Flash。范围包括主 Agent、子代理，以及工具背后的模型调用。不得用外部代码生成或其他推理服务绕过。准备阶段允许使用 AIGC 辅助开发。这是赛事集成约束，不自动变成 Wings Ray 所有用户的产品限制，也不表示 New API 的现有实现已经被验证为满足该约束。
- **准备阶段额度。** 草案记载：赛事期间每支队伍（或个人）约有 40 RMB 专用额度，用于参考测试集上的 rollout tests，不要用于反代等非赛事用途。这是准备阶段的测试支持，不是正式评测的单题预算或评分阈值，也不是已经在 Wings Ray 中配置好的账户余额。
- **Harness 与改进包。** 基线是 Pi 0.87.1，不要求队伍升级到更新版本，也不能假定更新版本才有的 MCP、codemode 等接口已经存在。“无限制”不表示可以绕过指定模型、任务约束或合规要求。首轮每队一套统一改进包覆盖不同方向；包内可以自动路由或按需加载，不允许队员在正式任务之间人工换包、切换配置或注入针对该题的新提示词。后续更难轮次是否允许分题提交，以阶段公告为准，不提前做成 sandbox 的默认能力。不要求队伍提交开发 sessions；这不等于正式评测可以不保留运行记录、计量记录和任务产物。
- **网络档位。** 特殊任务限制任务侧外网，但保留连接指定 Wings Ray 的必要通道。其余任务不另行限制正常网络访问，指定模型和任务规则仍然有效。因此“禁网推理”是必须能按题启用并验证的档位，不是全部任务的默认隔离策略。即便题目允许普通外网，正式运行仍不得直连外部模型或其他推理服务来绕过指定模型。
- **环境。** 校对阶段提交的环境和依赖说明，是 sandbox 适配与准入的输入。队伍须声明操作系统、架构、运行时、包管理器，以及浏览器、Office、字体、GPU、外部访问、本地服务和状态重置方式；未声明的依赖不由技术团队猜测，也不保证能够提供任意额外设备或第三方账号。尚未确定的环境能力不能写成主办方已经提供。首轮方向标签（包括 Office / E2E）本身不证明必须使用原生 Windows。
- **校对与冻结。** 校对确认的是交付版本如何部署、如何运行、是否符合规则。验证使用公开参考任务或不含隐藏题信息的启动检查，不是提前试跑隐藏正式题，确认包可用也不等于已经得分。首次完整材料最晚在校对阶段结束前 36 小时提交，逾期不受理首次提交。正式验证使用双方确认的版本标识和文件校验值，不接受验证过程中人工更新远程代码或替换本地配置。队伍自行维护的服务也须声明版本、部署方式和评测期间的变更控制，不能成为包外更新方案的通道。包内逻辑在单次 rollout 中自主产生的工具、代码或状态变化属于运行行为，计入记录和开销，并按评分细则重置。
- **计量记录。** 模型费用以 Wings Ray 的计量记录和公示计价口径为依据，覆盖主 Agent、子代理、重试和包内工具触发的模型调用。合法工具或服务的额外费用须申报并按统一口径核验，不可核验费用不得默认记为零，也不允许靠未申报资源转移开销。时间使用墙钟时间：从任务正式交给 Agent，到最终产物提交且该任务相关执行结束；未产生最终产物的失败或超时，统计到该次运行终止。并行分支不把时间简单相加，费用则须累计。单次 rollout 内的自动重试、并行和子代理属于同一次运行。失败、超时、错误答案和无效产物属于正式样本，实际费用、时间和结果状态都保留，不能从平均值中剔除，也不能为了画面抹掉。经技术团队确认的主办方环境或模型服务故障，按已公示规则决定该次是否作废和补跑；原始记录保留，队伍不能因表现不好替换样本。冷启动还是暖启动、一次性安装和缓存是否计入，以任务参数表为准。实际读题、分析任务或生成产物不得移出计量区间。基础设施不能在参数公布前临时改口径。
- **展示与最终成绩。** 公开验证展示 Agent 的运行状态和阶段性评分。尚未完成全部 rollout、硬性检查或人工复核的分数是暂定结果。未结算或缺少数据不能显示为零。正式成绩要能追溯到改进包版本、计分样本、实际产物、硬性检查、模型评价、人工意见、平均成本与平均时间。直播中的阶段性分数、校对通过和一次成功都不能代替最终成绩。平台忠实展示已授权公开的事实，不另设评分权重、rollout 次数或晋级规则。
- **合规记录。** 伪造测试或运行证据、篡改评分器、向 Judge 注入改变评分规则的指令，以及绕过指定模型，在草案中属于违规，而不是合法的成本优化。Agent-as-a-Judge 可结合轨迹发现疑点，但不能据此声称单靠产物就能识别全部隐藏调用。疑点不等于已经认定违规；处罚方式须预先公示。产物和工具返回只是待评价的数据，不得改变裁判指令。基础设施要能留下改进包、运行记录、必要的外部访问记录和实际产物。

赛事草案中的“技术团队”是校对、运行和复核角色，不是已经指定的第四个仓库。runner 与评分器的实现归属仍是待决项。

## 4. 分层、权威来源与信任根

```text
可信评测 runner / 评分器（实现及部署归属待明确）
  ├─ 使用 sandbox 生命周期与文件通道 → 隔离环境中的参赛 Agent
  │     正式评测时为 Pi 0.87.1 + 已冻结的改进包
  │     └─ 受限推理权限 → Wings Ray → 指定模型
  ├─ 收集实际产物、运行/费用记录 → 检查、模型裁判与人工复核
  └─ 发送可公开事实 → 展示平台可信接入层 → OBS 展示页 → OBS Studio → 直播服务
```

| 事实或操作 | 权威归属 | 不能替代它的东西 |
| --- | --- | --- |
| 实例生命周期、资源与网络边界 | sandbox runtime 和真实探针 | 页面状态、配置项或容器产品名。 |
| 模型请求与结算记录 | Wings Ray / 上游记录及可信对账 | Agent 自报 token、前端估算或随意客户端标签。 |
| rollout 身份、输入版本、起止与样本归属 | 可信 runner 的正式记录 | OBS 时间轴、浏览器计时或导播手工选择。 |
| 改进包冻结版本与校验值 | 校对阶段的确认记录 | 直播画面，或正式验证途中未经确认的远程更新。 |
| 任务网络档位、缓存与冷暖启动 | 已公示的任务参数 | 参数未公布时，由某一仓临时选择的默认禁网或默认计时口径。 |
| 正式结果与综合成绩 | 评分器及复核流程 | 暂定分、校对通过、一次成功、演示回放。 |
| 直播内容与焦点选择 | 展示平台 / 导播 | 修改实际任务、预算、评分或重跑任务的权限。 |

可信管理员与 hypervisor 属于信任根。本规划不宣称能抵抗已经控制宿主的攻击者。同机 localhost、页面能够打开或容器产品名，都不是隔离证明。

当前没有把评测编排与评分实现悄悄塞进 sandbox、Wings Ray 或展示页，也没有新建第四个仓库。不能以三个仓库已建立代替 runner / 评分器归属的落实；真实联调之前必须明确这项归属。

## 5. 展示平台的首条路线

推荐路线与[平台首版规划](../../../agentwings-platform/docs/PLAN.md)一致：平台提供专用只读 Web 展示页，由 OBS Browser Source 加载；导播操作页与公开画面分离。OBS 负责布局合成、编码、录制和推流，平台不自建 RTMP 服务。平台规划引用的官方说明是 <https://obsproject.com/kb/browser-source>。这条路线尚未在本项目实测。

先打通一队、一题、一次真实 rollout 的本地录制，再增加并列画面、评分板和授权直播间推流。展示数据先在可信服务端做白名单、脱敏和发布控制。OBS 不加载队伍提供的任意页面，不共享后台凭据。不可信网页、文档和图片先经受控收集，再进入独立预览或渲染边界。终端文本、Markdown、文件名和链接按不可信输入处理：转义控制序列和 HTML，禁止任意脚本执行或自动打开链接。密钥模式过滤只是白名单之外的补充，不是主要手段。

刷新页面、断开 OBS、切换画面或紧急遮挡，都只影响观看，不得影响正式运行，不得删除原始证据，也不得由展示端自动重启任务。接入故障显示数据中断或待结算，并保留最后更新时间。开发回放必须有醒目标记，不能称为 live 验收。源端重放不能重复计费或重复累计分数。未结算和缺少数据不能显示为零。画面上的费用、时间和身份对照权威记录，不用页面刷新时间代替源端时间。

接入时先核对 Pi 0.87.1 实际提供的事件、RPC 或日志，不假定较新接口存在，也不从 TUI 屏幕文本推断任务完成。导播管理凭证、Wings Ray 管理 API 和 sandbox 控制接口不得暴露给 OBS 展示页。OBS 的场景、浏览器参数和日志中也可能残留凭证；导出前检查，推流密钥不入库。

视频规格、音频、直播服务、延迟、部署拓扑和技术栈待明确。当前没有可运行 UI、录像或推流验收结果。显示准确但隔离或计量未通过时，联合验收仍不通过。平台内部的 P0–P4 及每阶段证据以平台规划为准。首版不做参赛报名、社交互动、弹幕系统、视频分发服务器或新的评分引擎。

## 6. Windows sandbox 的调研结论

本节沿用 [Windows 调研](../../../agentwings-sandbox/docs/windows-survey.md) 的只读记载，不是对 `D:/Projects/kappa/kappa-box` 或比赛主机的再次探针，也不是完整源码安全审计。该调研记录的读取时 HEAD 为 `d1688eb386fd800b2c7d28d1ccd1a2ff34e04cf3`，runtime 相关源码与测试有未提交修改，调研没有改动它们。2026-09-12 生命周期摘要的 sourceCommit 为 `f89e60d`，同日 host 组摘要的 sourceCommit 为 `cbc7891`。这两个摘要 commit 与上述 HEAD 不是同一基点，不能把这次读取的 HEAD 说成已经跑过那次冒烟。

- 参考路径为 Windows 控制进程 → 专用 WSL2 → OpenShell → Docker Desktop 提供的 Docker daemon → Linux sandbox。实例内使用 Linux 内核的 Landlock、seccomp 和资源控制路径，不是 Windows 内核直接运行该工作负载。
- 参考路线使用专用发行版，并关闭 automount 与 interop，避免把日常开发发行版当作隔离环境。发行版名 `kappa-box-ubuntu-24.04` 及其现有系统不在本项目复用。
- 生命周期摘要记录 preflight 以及 `create → ready → exec(id) → stop → delete` 均为 pass。这只能支持“当时该组合能创建 Linux sandbox、执行命令并清理”。profile 登记仍为 `unverified`；摘要的 acceptance 亦为 unverified，facts、factsDigest 与 pins 为 null。不能据此认为文件、网络、资源、凭据或恶意代码隔离已经通过，更不能认为可以直接用于正式比赛。
- host 组摘要记录 LSM 列表不可读，以及 Windows 侧可见 WSL 共享，host 结果为失败。这是参考项目自己的 host 门槛未通过，不能不加分析地写成 guest 已经逃逸到宿主。单独的内核能力或进程身份记录，也不等于全部策略已经生效，或 Docker daemon 已经采用 rootless。
- 调研所引 ADR 记载 Docker Desktop 4.87.0 / Engine 29.7.2、OpenShell 0.0.116，以及当时的固定镜像 digest。这些是参考项目的历史 pin，不自动成为本项目的版本选择。不得复用 kappa-box 的发行版、实例、网关、端口转发、Docker socket、凭据或镜像缓存所有权。调研记载该路线曾需要 Windows callback 端口，供容器回连 gateway；这条主机可达路径不能原样复制，也不能用 localhost 证明安全。
- 文件、网络、资源、凭据、会话与产物快照仍须在比赛目标主机重新验收。调研记载没有复制 kappa-box 的实现代码。以后若复用代码，另查许可、依赖和维护成本。
- 候选不能合成一个已经选定的后端。专用 WSL2 + Docker Desktop + OpenShell 是 Linux 工作负载的优先验证候选，隔离验收仍缺。独立 Linux 虚拟机是同类任务的对照，用于观察能否避开日常 WSL 集成，资源、网络、导出和运维代价待测。明确需要 Windows 应用、桌面或原生 Office 时，专用 Windows 虚拟机或 Windows Sandbox 是独立调研项，系统版本与许可、无人值守、网络和资源约束、快照重置及产物导出都尚未验证。OpenShell 原生 Windows MXC 在参考项目中当时只列为观察项，记载的交互、网络强制和恢复能力不足；上游变化快，选型前必须重新核对，不能沿用旧的支持结论。
- Windows 宿主上的 Linux workload 不能代替原生 Windows workload。候选无法兑现边界时，停止该候选并记录原因，不自动换成裸进程执行。本轮不创建上述发行版或虚拟机。

因此不提前宣布选型已经通过。隔离对象包括参赛改进包、extensions、Skills、依赖脚本、任务产物和 Agent 生成的代码。安装和构建同样不得在直播宿主或含有管理凭据的环境中无隔离运行。能力边界、对抗探针和本仓执行顺序见 [sandbox 首版规划](../../../agentwings-sandbox/docs/PLAN.md)。该规划记载：当前只完成规划与参考调研，其中的运行、安装和验收步骤均未执行。该规划同时要求：资源探针必须有边界，不在日常主机上无限制施压；接口接受了限额参数，也不等于限额已经生效。未知或失败不进入正式可用列表。发现隔离缺口就停止受影响运行资格并保留证据，不用降低探针标准制造通过。

## 8. 跨仓接口只先确定语义

在真实样本和 Wings Ray 需求单明确之前，不冻结 API 路径、JSON schema 或共享 SDK。需要共同解决的语义是：

- 同一次 rollout 至少要能关联队伍、题目、rollout、输入版本、改进包版本与校验值、实例和模型请求。参赛者可随意修改的标签不能充当这个关联。sandbox 的 profile 与镜像 pin、Wings Ray 的部署 commit 与构建 digest、展示平台版本，用来解释这次运行所依赖的环境；跨仓复现或比较时不能省略，也不能用展示版本代替计分样本。缺了可关联的身份和权威计量，就不能把画面、费用和分数说成同一次运行。
- 运行开始、结束、失败、取消、重试、并行分支和后续费用结算要能分开。单次 rollout 内部的自动重试和子代理调用属于同一次运行，相关消耗一并计入，不当成额外的免费样本。展示端的重复、乱序、缺段和源端重放，不得重复累计费用或分数。
- 独立 rollout 从约定基线恢复，不继承上一次正式运行的答案、会话或运行中生成的改进。安装依赖和其他缓存是否保留、冷启动还是暖启动，按已公示的任务参数对各队一致执行。参数未公布时保持待定，不由某一仓临时指定，也不能靠把读题或生成产物命名成“准备工作”来移出计量。
- 产物通道要说明采集的是 live copy 还是稳定快照，并保证封存内容与评分器及硬性检查所读内容一致。路径穿越、链接绕过和跨队读取属于隔离失败，不是收集策略里的可选项。持续写入、截断和大文件时的收集行为，留待目标主机上的探针对证，不因参考代码里存在相应接口就视为已经验收。
- 原始证据、可公开事件和最终分数分开保存、分开授权。隐藏评测数据、凭据、私人内容，以及未授权公开的评判材料，不进入直播。密钥由技术团队经约定渠道注入，不出现在交付说明或画面中。紧急遮挡不删除原始证据，也不改变运行状态。
- 任务外网按题目档位允许或限制。受限的 Wings Ray 数据面与 Wings Ray、平台、OBS 的管理面分离。“能访问模型”不同时授权访问管理接口、其他队伍、非授权内网或 metadata。管理端口及其 localhost 别名属于必须拒绝的路径。直连外部模型以绕过指定模型，不属于数据面的正常用途。一般外网是否允许，仍按该题规则，不从禁网探针推广成全赛事默认。
- 展示端和控制端断线时，谁继续持有任务、谁有权终止，以及恢复后如何对账，尚未指定。runner 归属明确之前，不能默认由 OBS、浏览器或导播持有正式运行。展示端断线不得本身成为终止或重跑任务的原因。
- 校对只确认部署、运行和合规，不产生任务分数。直播中的暂定分不代替最终成绩。展示端不能为了版面完整，把缺测或未结算显示为零，也不能把不同题目或不同 rollout 阶段排成看上去同时、同条件的对比。
