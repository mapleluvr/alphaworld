## 工作定义

本次将“自然”暂理解为：输出的组织方式、详略、语体和衔接适合任务、材料、读者与目标风格，较少出现与内容无关的固定动作。

人机来源、表达自然、作品质量是不同维度。人类常用不等于优质，模型常用不等于错误；这里不以隐藏 AI 来源或检测器得分为目标。

## 值得借鉴的研究做法

1. 保留被撤回的判断，查明测量错误后改变规则，而非持续为旧结论辩护。这与现有 skill 的有范围修正相符。
2. 按模型、作者与体裁检查差异，目标风格优先于人类语料的平均值。
3. 先检查命中样本的含义，再计算频率。上游选择抽查 20 条是一项工作约定，不是普遍充分的样本量。
4. 区分特征的总量与条件分布。问句标题每千字更多，可能只是标题总量更多；真正的问题不同，分母也应不同，不能统一只保留一种分母。
5. 区分可观察形式、语义功能和改写权限。形态计数可供筛查，不能直接决定一句话应不应该改。

## 值得作为候选观察的现象

下列数字均为上游报告值，未独立复算。原始语料不公开，且公开测量实现存在下述不一致。

| 现象 | 上游报告 | 对本项目的启发 |
| --- | --- | --- |
| 刻意制造节奏缺乏依据 | 相邻句长差两侧均为 21.7；句长 CV 比为 0.87；段长稳健离散度比为 0.94 | 节奏随内容、视角和语体变化，不规定长短句配额 |
| 删除常见修辞可能适得其反 | 比喻标记人类约为 AI 的 2.4 倍，正文问句约 17 倍；句内排比不支持一律删除 | 保留有作用的问句、比喻、排比与有意重复，尤其不外推为文学禁令 |
| 过度使用翻案构式 | “不是……而是……”约 3.4 倍 | 先陈述有依据的判断；实际发生的纠错或有意义的对比继续保留 |
| 重复的呈现动作 | 提示语冒号约 3.8 倍，空转句引列表约 9.4 倍；相邻句同构约 2 倍 | 注意没有增加理解的宣布、复述和齐整列举；格式本身不构成问题 |
| 材料密度不同 | 人类数字密度约 2.8 倍，时间锚点约 2.6 倍 | 让已有事实承担判断；非虚构缺材料时取证，创作中按授权构造细节 |
| 回指与衔接 | 段首零主语评论约 4.4 倍，衔接词总量却接近 | 检查读者能否确定所指及关系，而非机械增删连接词或补“这” |
| 模型和作者差异很大 | 破折号 DeepSeek 5.16/千字，GPT 0.11；人类来源之间也悬殊 | 不以某一模型或单一作者的习惯制定通用禁用表 |

以上是研究启发。它们没有证明按这些规则改写会提高自然度、规划质量或文学质量。

## 证据链的局限

### 数据与推断

- 上游自述 300 篇 AI、329 篇人类文章；不公开语料，因此不能核验采样、标签、生成条件和统计值。
- 话题与体裁宣称范围对齐，但局限章节承认未严格配对。AI 只给话题、不联网；人类公开文章可能带有采访或研究材料。数字密度差异因而不能直接归因为模型文风。
- 未见逐篇不确定性估计、保留测试集或真实读者对改写前后的盲评结果。固定倍率门槛不等于统计显著性，更不等于改写收益。
- `RESEARCH.md` 对翻译腔声称有 2.6–5.3 倍的人类对照，`README.md` 局限部分又称这部分仅使用 AI 绝对频率。公开材料尚不足以消解这一冲突。
- 人机特征频率差异不能自动证明一个具体句子出自 AI，也不能自动证明它妨碍阅读。当前材料没有直接支持规划任务和小说创作的干预效果。

### 公开实现的三个可复现反例

直接导入未修改上游脚本的实际函数，用少量合成输入探测其测量定义。它们不是人机语料，不用于估计真实发生率。

复现命令：

```powershell
python -B research/probe_upstream_metrics.py
```

脚本：`probe_upstream_metrics.py`；实际结果：`upstream-metric-probes.json`。

1. `check-structure.py` 的 `paragraphs()` 按单个换行拆分，而研究声明按空行分段。同一段文字仅加入源码软换行，测得段数便从 1 变成 2。
2. `COMMENT` 与 `ANAPHOR` 都锚定字符串开头。输入“值得注意的是，这个接口仍然兼容旧版本。”仍被判作缺回指；去掉“这个接口”的对照句也一样命中。实现不检查评论句内部已有的明确对象。
3. `compare-human-ai.py` 中名为“序数词当小标题”的规则，对三个 `## 一、…` 标题命中 0 次，对普通正文“首先，… / 其次，… / 最后，…”命中 3 次；与 skill 的目标及豁免范围不符。

另外，比较脚本输出的倍率为人类/AI，研究表格声明 AI/人类，使用时需要换算。结构指纹仅比较逗号数、冒号/括号及长度档，不能据此确认语法成分顺序相同。

这些反例足以限制对公开指标的信任；无法由此证明未公开语料上的全部数字错误，也没有修改上游实现。

## 不宜直接移植的规则

### 频率直接升级为禁令

“模型多用一种形式”至多支持进一步检查。在修订中应能指出所指不清、重复、逻辑变化或风格不合等具体问题。现有研究没有验证禁用冒号、长定语、对举句等行为会改善整体作品。

### 白名单与原框架锁定

上游定位是成稿的有限清理，逐字保留未命中内容、固定段落与标题结构在该范围内有意义。直接用于规划、初稿生成或文学创作，会冻结恰恰需要生成和调整的结构。

### 信息守恒与实际例子冲突

- “这不是一个工具的问题，而是一个思维方式的问题。”改为“这是思维方式的问题。”丢失对工具问题的排除；只有确认该排除不承担含义才可删。
- “采集、存储、展示”改为“从采集到展示”，不再明确保留存储环节。
- “用户只在乎”改为“用户首先在乎”，改变了排他断言的强度。若原断言过强，这是另需依据的内容修正。

应保护事实、限定、否定、量词与因果关系，而不是把“每个实词必须在原文出现”当作语义守恒的充分标准。文学创作则在授权的虚构空间内生成细节，守住既定设定和视角；不能把非虚构的禁止新增套到创作任务。

## 与 template_skill 的结合建议

采用“任务与材料决定行动，也决定表达形式”作为连接点。保留主文件的工作机制，表达指导只增加少量默认判断；具体语言问题放入按需参考的示例。

| 任务 | 适合的生成依据 | 自然表现的候选检查 |
| --- | --- | --- |
| 规划 | 已知依赖、关键未知、风险与执行条件 | 明确部分可连续执行；篇幅和检查点落在实际难点，而非各阶段等长 |
| 文档 | 读者需要完成的工作、找到的信息与已有事实 | 操作可找到、所指清楚、材料支持结论；目录/列表/表格承担检索或对照功能 |
| 文学 | 人物可知信息、欲望、行动后果、叙述视角和目标风格 | 细节推动经验或情节，声音与设定一致；保留有作用的重复、含混和留白 |

这些是待检验的设计建议，不是上游已经证明的结果。文学的不同流派也不应统一为“全部写成动作”“一律取消解释”。

可考虑的短节草案（未写入主文件）：

> 根据任务用途、读者和已有风格选择组织方式与语体。让依赖关系组织计划，让读者的使用路径组织文档，让视角与情节组织叙事。
>
> 用材料和有意设定形成具体内容。事实性写作区分已知事实与推测；虚构写作在约定的世界和视角内发展细节。
>
> 让段落承担当前需要的作用，并使读者能理解必要的承接关系。详略与节奏随内容重心变化。
>
> 修订针对实际影响理解、连贯或目标风格的部分，保留仍有作用的表达。最终输出采用用户所需的形式；过程说明只在用户要求或影响成果使用时附上。

最后一项也针对现有“结束与报告”：规划执行中的状态报告有用，但写小说时默认在结尾附带“已完成、已验证”会破坏交付形式。必要的事实限制仍须说明，呈现位置应随任务选择。

## 如何验证建议

以用户实际使用的规划、文档和文学任务分别比较：当前 template、当前 template 加候选表达指导。使用同一模型与材料，记录模型版本和生成条件，改变呈现顺序做匿名偏好评阅；不让评阅者只按新规则打分。

同时看任务完成、事实与设定保持、读者自然度偏好、返工和实际成本。句式计数仅作诊断，不能充当验收代理。先检查最小样例能否暴露问题，出现有价值信号后再扩展；本次未运行这类模型实验。
