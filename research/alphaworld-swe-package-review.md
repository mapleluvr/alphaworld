# Alphaworld-SWE：第二轮评议与独立封装

本轮依据用户对候选修订的评议，建立可单独安装的 `alphaworld-swe` 包。目标仍是软件工程、工程文档与技术协作，不恢复通用文学写作范围，也不把这次评议追加为每个任务的检查流程。

运行入口见[独立包说明](https://github.com/mapleluvr/alphaworld-swe#readme)与[主文件](https://github.com/mapleluvr/alphaworld-swe/blob/main/skills/alphaworld-swe/SKILL.md)。
前一轮取舍保留在[候选评议](alphaworld-swe-candidate-review.md)中。

本轮记录之后，该包已迁出为独立公开仓库 [mapleluvr/alphaworld-swe](https://github.com/mapleluvr/alphaworld-swe)，本仓库不再包含 `packages/`。下文对包内路径的记述按当时状态保留。

## 怎样看待这份评议

四项文本判断基本有材料支持：历史记录可能承载有效约定；试写不只用于排错；文档分工不能预先覆盖具体使用条件；“已知的重议依据”比要求填写重启阈值更能容纳证据缺失。它们分别对应候选中的明确措辞变化。

其中，固定 FAQ、ADR 的问题不仅是项目可能没有这些目录。即使它们存在，读者完成当前操作必需的兼容条件仍可能应当出现在使用路径上。这次修订处理的是工作关系，而不只是文件名的可移植性。

这些判断不能进一步证明“完全吃透”“堵死漏洞”或真实模型的行为已经改善。措辞减少了某种误读空间，模型是否据此改变行动仍需要实际运行证据。

主文中的工程例子确实降低了对附件的依赖，但“内联六个情境的浓缩骨架”只适合作为一种阅读解释，不宜倒写成此前已经完整规划好的架构方案。上轮实际围绕信息效力、文档用途与留存作了局部修订，并没有测量主文对附件的替代比例。

因此，不采用评议中的“80% 以上方向校准”或“99% 会认为值得落盘”作为事实。前者没有定义覆盖率及判定方法，后者是对模型倾向的推测。开工前核对的候选正文为 2,197 个 Unicode 码点、其中 1,730 个汉字，统计排除了 frontmatter；这不是 token 数，也不能支持文中“1400 字”对应的上下文收益结论。

## 留存判据：接受比较现有材料，调整其表达

评议指出，“后续有作用”容易被泛泛的“有助于协作”满足。这个风险值得处理，但不能仅凭对模型性格的描述认定它必然发生。原候选的阻碍判据本来也面向未来读者，并非只考虑当下；两种表述的行为差异仍未测试。

本轮采纳与现有代码和说明作比较的方向，但没有直接加入“在代码与现有说明之外”。这句话可以理解为比较新增价值，也可能被模型理解成只保留现有材料没有的信息。后一种解释会伤及第六个情境：内部资料已经存在，却无法供外部接手者离线使用；必要重复在这里承担新的交付作用。现场手册将判据放在操作附近，也不必创造新事实才有价值。

新包采用：

> 一次草稿或实验可以只服务于当前推理，不必成为长期维护的文件；是否留存，要结合代码与现有说明在实际使用条件下能否承担同一作用，以及新增材料对后续使用、协作或重新判断的帮助与维护成本来判断。

这里的比较是已有材料能否在实际条件下承担同一作用，而不是有无文字或信息重复。维护成本进入判断，但没有增加评分表、强制论证段落或留存审批。

三个已有情境帮助检查这项取舍的含义：

- 已有且可达的调用说明足以支持同一项工作，不因刚完成一次推理便另建说明。
- 外部离线交接需要重复获准交付的信息，因为内部链接无法承担当前说明。
- 决策记录保存实现本身无法交代的历史条件，不能因暂时没有操作障碍就丢弃。

这些是语义上的对照，不是三次真实模型测试；它们也没有被追加进主文成为必做清单。

## 案例合并与按需读取

接受将第七情境并入新包的 `references/document-work-cases.md`，放在第六例之后、总结之前。它与决策记录、偏好迁移共同讨论判断的条件与持续效力，集中维护有实际关联，不只是追求目录整齐。

合并只发生在新包。通用版的六例与原主文不变，根目录第七情境保留为讨论来源。新附件的来源说明分别标明：前六例为构造情境，第七例没有附可追溯运行记录，只按所述条件分析。没有为了合并方便就将七例全称为构造案例或实际实验。

新包路由采用评议建议的方向：

> 辨认文档参与的工作、处理历史限制（如旧 Non-Goals）与当前改动的冲突，或根据使用反馈形成和复用编辑偏好时，按需读取文档工作情境中相关部分。

它将抽象用途与具体冲突并列，仍保留按需选读。这里没有声称路由问题已经解决：模型能否识别触发情境、是否实际读取及怎样使用附件，需要在运行记录中观察。简单任务不读附件也可能正确完成，读取次数本身不是收益指标。

## 独立包的边界

包位于 `packages/alphaworld-swe/`，有自己的 `package.json`、README、主文和三个附件。独立表示可以单独安装、搬移和加载，不表示另建了远程仓库。根目录 `package.json` 继续只暴露通用版，安装原包不会隐式启用 SWE 分支。

主文基于候选，初次封装在留存判据、合并后的参考入口和包内路径上继续修改。封装时还删去了写作示例，并另写了思想说明；这两项处理把任务范围的专门化扩大到了不应改写的来路与写作取向，已在用户指出后撤回，具体纠正见文末。所有运行所需附件均在包内，不通过相对路径依赖通用版或研究目录。

根目录两份候选保留为讨论材料，仅修复标题、换行等格式问题。SWE 分支后续修订以独立包内主文为入口，避免两份并行候选默默分叉。导航和仓库说明已据此更新；历史快照、研究 submodule 与原技能内容保持不变。

## 格式诊断与验证边界

用户反馈此前存在三条 markdownlint 诊断。本轮主动 LSP 查询仍返回零发现，随后直接使用本机 markdownlint 0.41.1 的默认规则检查三份上一轮文件，发现五条：两处末尾换行缺失、一处独立文档从二级标题开始，以及两处长行。该结果不能直接等同于原来那三条诊断，但说明之前仅凭编辑器和 LSP 返回值宣称 Markdown clean，覆盖不足。

本轮已修正上述五处格式问题，没有关闭规则或放宽阈值。独立第七情境使用一级标题，合入附件时使用二级标题。扩大检查到十二份新建或涉及的 Markdown 后，默认规则另报十八条长行提示；用户随后明确要求不再处理 Markdown 问题，因此停止格式修复，不宣称完整 lint 通过。

本轮没有付费调用模型、执行 SWE 行为对照、全局安装 skill、创建远程仓库、发布或提交。能否减少冗余落盘和错误阻断，以及是否保留了有用的生成与文档协作能力，仍是未验证项。

## 后续纠正：沿用思想原文与写作取向

用户指出，Alphaworld-SWE 的 Alphaworld 思想来源不需要重写，原有写作原则与风格也适用于这个 skill 的创作。此前以 SWE 用途重新概括思想说明，删去了原文中的形成过程、自然表达研究与 Structural Reflection 等内容；它不是几处包内细节的适配，而是未经要求的重新取舍。

本次恢复了思想说明全文，只在开头标明沿用关系、在末尾说明主文链接、六例与新增第七例、来源仓库研究路径的差异。原有论述及判断强度不变。完整示例也一并恢复，使原文所引用的文学与论述案例仍可在包内阅读；保留它们不改变 SWE 的任务范围。

主文补回原有的写作指导：声音、结构与节奏结合材料、视角和目标风格形成；事实性内容保留限定并区分事实与推测；编辑已有内容时保护原意与判断强度。它们既用于工程文本，也适用于本 skill 及其说明的创作，而不是另立一套 SWE 文风规则。

纠正后已核对：移除两处明确标注的包内说明，思想附件与 Alphaworld 原文逐字一致；示例附件与原版字节一致。搬移后的原生包解析和 skill 加载通过，十三处包内相对链接均有效；原版文件与历史材料未改。再次执行 `npm pack --dry-run --ignore-scripts --json`，仍为六个分发文件，恢复全文后的未展开体积为 44,961 字节。Pi-lens 的五条 Marksman 提示均为同名附件造成的链接歧义，实际包内相对路径已验证存在；按用户要求未为 Markdown 告警重写原文。本次未进行行为效果验证。
